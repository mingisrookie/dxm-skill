# DXM 项目协作

**精简规则，保留能改善决策和交付的能力。**

DXM 为 AI 补充项目事实、需求澄清方式、验证依据和授权边界，不再充当任务管理器。模型负责调查、规划和实现，DXM 不规定它必须拆几步、调用几个代理或填写多少状态文件。

## 当前版本

当前源码版本为 **3.0.0**。发布状态与下载资产以 [GitHub Release](https://github.com/mingisrookie/dxm-skill/releases/tag/v3.0.0) 为准。

仅安装核心规则使用 `dxm-skill-core-v3.0.0.zip`；需要 Grill 等全部能力，使用 `dxm-skills-bundle-v3.0.0.zip` 并按需安装其中的技能。`SHA256SUMS` 用于校验两个下载包。

## 怎么使用

将 `skills/dxm` 安装为独立技能，通过宿主的技能入口选择 `dxm`，或使用项目约定的 `/dxm`。这里的 `/dxm` 是触发约定，不是新增的终端命令。

默认读取和维护当前项目的协作规则；“只审查”保持只读，明确要求实施才修改。已有人工规则按实际需要增补，不覆盖整份文件。用户级规则或配置只有在明确指定并授权时才修改。

核心技能没有运行时依赖、安装脚本或工作流 CLI，也不要求 Python。Python 仅用于本仓开发测试。安装时只复制所选技能目录，不复制仓库里的本地状态、备份和测试产物。各独立技能目录均附带本仓原有的 `LICENSE`。

## 保留的增强能力

Grill 保留。普通澄清先查证据，只问会改变结果的重要未知；用户主动要求深入讨论时，保留一轮一个关键问题、给出建议和取舍、等待回答的节奏。用户要求停止或关键决策足够明确时结束，不把结束访谈当成对实施或高风险操作的授权。

可选技能可以分别安装，也可以独立使用：`grilling` 提供深入压力测试；`grill-me` 保留熟悉的显式调用入口；`grill-with-docs` 提供证据型澄清；`domain-modeling` 维护业务术语和重要取舍。核心 DXM 不要求安装它们，缺少时按内联规则处理。

真实验证、反例审查、项目知识、跨会话交接和工作区卫生同样保留。文档和审查按任务风险使用，不再每次建立固定目录或提交机器回执。自身复核不能冒充独立审查。

## 本次删除

Trellis 的代码、CLI、路由、模板注入、配置适配、完成校验和相关旧测试从当前产品删除，不留兼容调用或改名后的替代状态机。旧的批量脚手架和本地任务契约同时移除，不再分发可被导入重启的历史模块。

新技能不创建或维护隐藏任务状态，也不强制五份文档。已有项目自身的审批、合规和验证要求仍然有效。

升级不能只覆盖新文件：旧安装目录中多出来的模块不会自行消失，宿主缓存的技能也未必立即刷新。操作和数据保护边界见 [迁移说明](docs/migration-v3.md)。

## 开发验证

```text
python -B -m unittest discover -s tests -v
git diff --check
```

CI 运行整个当前测试目录，不挑选一个小测试文件来掩盖其他失败。测试验证包结构、引用、编码、规则边界和发布打包；它不证明模型在真实对话中的遵循率。

尚未执行真实模型 A/B 评估，不宣称改造后更快、更便宜或成功率更高。后续应在相同模型、宿主、权限和项目快照下，比较任务完成质量、越权与误报、澄清负担和实际成本；深入访谈的质量不能只按对话轮数衡量。

本仓保留的长期中文文档服务于本仓维护，不再作为向其他项目批量生成文档的模板。

## 维护者发布

版本号与中文更新日志一致后，推送对应的正式版本标签。CI 先运行九组跨平台完整测试，再构建核心包和完整技能包，上传 Release 草稿，重新下载并核对 SHA-256，最后发布并检查 Latest。

`tools/package_release.py` 仅用于本仓打包，不进入安装后的技能目录。发布授权来自维护者推送正式标签，不在普通开发或 PR 测试时创建 Release。
