# 升级到 DXM 3

这是破坏性升级，不提供旧 CLI、旧任务协议或 Trellis 兼容模式。新核心是无运行时脚本的技能包。

## 安装副本

先确定宿主实际读取的是哪个技能目录，记录当前版本并检查其中是否有人工作出的修改。不要把仓库源码目录等同于已安装目录，也不要猜测固定用户路径。

更新时使用干净安装或先将已确认的旧技能目录移到宿主不会扫描的有限备份位置，再安装新包；不要仅覆盖同名文件，否则旧 `scripts/`、`contract/` 和模板仍会残留。不要通过调用被删除的旧命令进行升级。

核心包只需安装 `skills/dxm`。访谈和领域技能是独立可选包，不作为新版本运行的依赖。安装后读回实际 `SKILL.md`、版本及包内容，按宿主支持的方式重新发现技能或开启新会话。没有重新读回，不声称已生效。

## 既有项目

先检查项目内的 `.agents/skills/`、`.codex/agents/`、hooks、配置和 `AGENTS.md` 等真实入口。只处理已确认由旧集成生成且属于本次授权范围的项目级条目，保留其他工具和人工配置。不要因为名称相近就删除。

先备份，再移除旧调用、文档中的活动指令、模板注入和专用 Git 属性。处理混合配置时只删除相应条目；不要用整个文件覆盖未知内容。

`.trellis/` 中可能含有用户的需求、规格、决策和历史证据。将仍有价值的项目事实移入获准的现有文档；历史目录可移到项目和宿主扫描路径之外的备份位置，不应自动递归销毁。已有 `.dxm/` 数据同样不被新版本读取，不自动删除。

`.gitignore` 继续忽略旧私有状态目录是防止意外上传，不是集成、调用入口或兼容层。旧标签和历史更新日志用于追溯，不回写历史来制造“从未依赖过”的假象。

不默认修改全局安装、卸载共享工具、影响其他项目或已经打开的会话。用户另行授权后才处理这些范围；项目级入口清理不能声称已完成全机卸载。

## 验收

当前核心包不存在旧脚本和契约目录，包内不含 Trellis 名称或路径；无外部任务管理器依赖，单独复制核心即可使用。实际使用项目不再暴露旧专属 skills、agent 配置或 hook 调用。

普通明确小修不建立流程文件；只读任务不落盘；深入 Grill 可独立触发、可停止，并保持权限边界。无法实际运行宿主或模型评估时说明该验证尚未完成。
